# نسخة NovaCortex المحلية للمسابقة

هذه نسخة مستقلة ومبسطة من قلب NovaCortex، مخصصة لتحدي سؤال وجواب فوق وثائق مجهولة تصل وقت المسابقة. لا تستخدم Telegram أو Groq أو Serper أو حقائق جامعة اليرموك. كل المعالجة والاسترجاع والإجابة تتم محلياً عبر Ollama.

## ما أصبح جاهزاً قبل وصول البيانات

- تحميل PDF وDOCX وPPTX وXLSX وTXT وMarkdown وHTML وJSON وCSV.
- استخراج جداول PDF وDOCX وPPTX وXLSX إلى Markdown قابل للبحث.
- الاحتفاظ باسم الملف ورقم الصفحة والقسم ونوع الوثيقة.
- كشف ملفات PDF التي تبدو ممسوحة ضوئياً وتحتاج OCR.
- تقرير منظم لكل ملف يوضح نجاح الاستخراج أو حاجته للمراجعة.
- إزالة محارف Unicode المخفية وضوضاء صفحات الويب الأساسية.
- إزالة الرؤوس والتذييلات القصيرة المتكررة بين صفحات PDF.
- تقسيم Parent–Child: أجزاء صغيرة للبحث وسياق أكبر للإجابة.
- التعرف على العناوين والمواد القانونية وأكواد المساقات كحدود بنيوية.
- وضع اسم المصدر والصفحة والقسم داخل نص كل Chunk قبل إنشاء الـembedding.
- دمج الأجزاء القصيرة بدلاً من إنتاج أجزاء عنوان فقط.
- Embeddings محلية على دفعات عبر Ollama `/api/embed`.
- فهرس Chroma محلي دائم.
- BM25 عربي/إنجليزي بدون اعتماد إضافي.
- دمج Vector Search وBM25 باستخدام Reciprocal Rank Fusion.
- تعزيز التطابق الدقيق للأرقام.
- منع مصدر واحد من احتلال جميع النتائج.
- استرجاع Parent كامل بعد العثور على Child مناسب.
- إجابة مقيدة بالأدلة مع Structured Output ودرجة حرارة صفر.
- التحقق من أن Citation يشير إلى Evidence ID موجود فعلاً.
- LangGraph بمسار ثابت: تحقق ← استرجاع ← سياق Parent ← إجابة موثقة.
- قياس زمن كل مرحلة وعرض النص الداعم مع المصدر.
- MCP اختياري يعرض البحث والإجابة والمصادر من المحرك نفسه.
- أوامر لفحص البيئة، وبناء الفهرس، وفحص الاسترجاع، والسؤال، والتقييم.

## التحضير على الجهاز قبل المسابقة

1. تثبيت Ollama والتأكد أنه يعمل محلياً.
2. تنزيل نموذج المحادثة ونموذج الـembedding مسبقاً. النموذجان قابلان للتغيير من متغيرات البيئة.
3. إنشاء بيئة Python وتثبيت المتطلبات:

```powershell
py -m venv .venv-hackathon
.\.venv-hackathon\Scripts\Activate.ps1
pip install -r hackathon_requirements.txt
```

4. انسخ `hackathon.env.example` إلى `hackathon.env` واضبط القيم بحسب النماذج التي يحددها المنظمون.
5. تجربة النظام على مجموعة وثائق عامة غير مرتبطة بالمسابقة.
6. الاحتفاظ بنسخة محلية من حزم Python ونماذج Ollama إذا كان الإنترنت داخل المسابقة غير مضمون.

## أوامر التشغيل

فحص Ollama والنماذج:

```powershell
python hackathon.py doctor
```

ضع الوثائق داخل:

```text
hackathon_workspace/documents/
```

افحص الاستخراج والـchunks أولاً بدون Ollama:

```powershell
python hackathon.py preview
```

سيُنشأ تقرير عينات في `hackathon_workspace/chunk_preview.json`. راجع أقصر وأطول الأجزاء والعينات الموزعة قبل إنشاء الـembeddings.

ثم ابنِ الفهرس:

```powershell
python hackathon.py ingest
```

افحص Retrieval بدون استهلاك وقت نموذج المحادثة:

```powershell
python hackathon.py inspect "السؤال هنا"
```

اطرح سؤالاً كاملاً:

```powershell
python hackathon.py ask "السؤال هنا"
```

أو افتح جلسة تفاعلية:

```powershell
python hackathon.py chat
```

ولواجهة عرض محلية للحكام:

```powershell
streamlit run hackathon_ui.py
```

تتيح الواجهة فحص البيئة، ومعاينة الـchunks، وبناء الفهرس، وطرح الأسئلة، وعرض المصادر وتفاصيل الاسترجاع والزمن.

ولتقديم محرك المعرفة إلى أي MCP Client متوافق:

```powershell
python hackathon_mcp.py
```

يعرض الخادم أدوات `search_documents` و`answer_from_documents` و`list_documents`
و`get_source_page`، بالإضافة إلى مورد لحالة الفهرس. MCP طبقة اختيارية؛ واجهة
Streamlit وأوامر المشروع تعملان من محرك RAG نفسه ولا تعتمدان عليه.

بعد إنشاء ملف تقييم من نسخة `hackathon_eval.example.json`:

```powershell
python hackathon.py evaluate hackathon_eval.json
```

يمكن تجاوز المسارات والنماذج من سطر الأوامر بدون تعديل الملفات:

```powershell
python hackathon.py --documents C:\challenge\docs --index C:\challenge\index --chat-model MODEL_NAME --embedding-model EMBED_MODEL ingest
```

## ما يجب عمله عند وصول البيانات

### أول 15 دقيقة: جرد الملفات

- عدد الملفات وأنواعها وأحجامها.
- لغة المحتوى.
- هل PDF نصي أم صور ممسوحة؟
- هل توجد جداول كثيرة؟
- هل توجد عناوين واضحة أو مواد مرقمة؟
- هل توجد نسخ مكررة من الوثيقة نفسها؟

### 15 دقيقة بعدها: فحص الاستخراج

- افتح النص المستخرج من أول وآخر صفحة ومن صفحات عشوائية.
- افحص ترتيب العربي والجداول.
- ابحث عن رؤوس وتذييلات وضوضاء متكررة.
- تأكد أن أرقام الصفحات والمصادر صحيحة.

### تخصيص الـchunking

ابدأ بالإعدادات الافتراضية:

- Parent: 3600 حرف.
- Child: 900 حرف.
- Overlap: 140 حرفاً.
- الحد الأدنى: 100 حرف، مع قبول الأقسام القصيرة إذا كانت وحدة مكتملة المعنى.

ثم عدّل حسب البنية:

| نوع البيانات | الاستراتيجية |
|---|---|
| لوائح وقوانين | مادة أو بند لكل قسم |
| أسئلة وأجوبة | السؤال مع جوابه |
| وصف عناصر أو منتجات | عنصر مستقل |
| جداول | عنوان الأعمدة مع مجموعة صفوف كاملة |
| كتب وتقارير | فصل ثم عنوان فرعي |
| كود | دالة أو Class |
| شرائح | شريحة أو مجموعة مترابطة |

لا تغيّر حجم الـChunk اعتماداً على الانطباع فقط. افحص 20–30 جزءاً، ثم اختبر هل المصدر الصحيح يظهر ضمن أول خمس نتائج.

### اختبار Retrieval قبل الإجابات

أنشئ بسرعة 10–20 سؤالاً يمكن معرفة مصدرها يدوياً. استخدم أمر `inspect` وتحقق من:

- ظهور الملف الصحيح ضمن Top 3 أو Top 5.
- احتواء الجزء على الجملة التي تجيب السؤال.
- عدم سيطرة ملف واحد على جميع النتائج.
- صحة الصفحة والقسم.
- نجاح الأسئلة التي تحتوي أرقاماً وأسماء دقيقة.

إذا Retrieval غير صحيح، لا تعدّل الـprompt أولاً؛ أصلح الاستخراج والـchunking والـembeddings.

### اختيار الـembedding

- استخدم نفس النموذج للفهرسة والاستعلام.
- إذا كان نموذج الـembedding يتطلب صيغة مختلفة للسؤال والوثيقة، اضبط `OLLAMA_EMBED_QUERY_PREFIX` و`OLLAMA_EMBED_DOCUMENT_PREFIX` حسب توثيقه؛ اتركهما فارغين للافتراضيات الحالية.
- لا تغيّر النموذج بعد بناء الفهرس إلا مع إعادة `ingest`.
- قارن النماذج على أسئلة فعلية من الداتا.
- اختر الأسرع إذا كانت الدقة متقاربة.
- إذا كانت الوثائق عربية أو متعددة اللغات، اختبر ذلك صراحة ولا تعتمد على اسم النموذج.

### اختبار الإجابة

اختبر ثلاث حالات على الأقل:

1. سؤال مباشر له جواب واضح.
2. سؤال يحتاج جمع معلومتين من قسمين.
3. سؤال غير موجود، ويجب أن يرفض النظام اختراع جواب له.

## تحسينات اختيارية بعد نجاح الأساس

- OCR للملفات الممسوحة إذا ظهرت في الداتا.
- Reranker محلي إذا كانت السرعة تسمح.
- Query rewriting لأسئلة المتابعة الغامضة.
- واجهة Streamlit أو Gradio.
- عرض النص الداعم بجانب الإجابة.
- قياس Recall@3 وRecall@5 وزمن الإجابة.

لا تبدأ بهذه التحسينات قبل نجاح Loader → Chunking → Retrieval → Citation من البداية للنهاية.

## عرض المسابقة المقترح

اعرض للحكام:

1. أن النظام يعمل بلا إنترنت.
2. الملفات التي تم تحميلها وعدد الأجزاء الناتجة.
3. جواباً مع اسم الملف والصفحة.
4. سؤالاً مركباً يستخدم أكثر من مصدر.
5. سؤالاً غير موجود يرفض النظام الإجابة عنه.
6. نتيجة تقييم صغيرة توضح دقة الاسترجاع والزمن.
